## Execution-judgment gap, internalized debate, and KV-cache capacity

**Agents execute well; they judge poorly.** At 76% success on open-ended tasks and task duration growing from ~4 minutes to ~12 hours year-over-year, execution capability is demonstrably strong. The constraint is judgment: choosing which problems matter, setting direction, deciding what to work on. A measured edge exists — 64% win rate on suggested experimental direction versus chance at 50% — but it is modest, not dominant. The practical implication: the closer a specification is to a complete executable description, the more reliable the agent; the more the agent must decide what to do rather than how to do it, the less reliable it becomes. See [Planning → The Execution-Judgment Gap](../concepts/planning.md) and [Evaluation → Coding Agent Capability Benchmarks](../concepts/evaluation.md).

**Multi-agent debate can be distilled into a single model.** A two-stage post-training pipeline — SFT on debate transcripts, then RL with progressive length clipping — forces a model to internalize debate reasoning rather than verbalize it. The result on 7–12B models: 5–16x fewer tokens while matching or exceeding explicit multi-agent debate on standard reasoning benchmarks. A notable byproduct: internalization creates distinct agent-specific activation subspaces in the model, which are steerable — unwanted reasoning personas can be suppressed via negative activation steering with minimal performance impact. See [Multi-Agent → Internalizing debate into a single model](../concepts/multi-agent.md).

**KV-cache quantization multiplies effective context capacity 3–5x.** Quantizing the KV cache — Hadamard rotation to spread outliers, variance normalization, then asymmetric low-bit quantization (4-bit keys, 2-bit values) — matches FP16 accuracy, delivers ~1.3x throughput gain, and requires no per-model calibration. Since the KV cache is what accumulates as context grows through an agentic session, more capacity per GPU directly extends effective context windows on fixed hardware. See [Agentic Loop → Inference Speed and Agentic Throughput](../concepts/agentic-loop.md).

**A concrete sandbox for agents executing untrusted code.** gVisor (a user-space Linux kernel) layered over each container, with an egress allowlist restricting outbound connections to the model API only. Agents refuse to start outside the sandbox — making accidental unsandboxed execution a hard failure rather than a silent risk. Pairing this with tiered autonomy (the same pipeline runs as interactive skills or fully autonomous) means the sandboxing discipline holds regardless of how the agent is invoked. See [Agentic Loop → What Practitioners Actually Do](../concepts/agentic-loop.md).
