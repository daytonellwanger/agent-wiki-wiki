## Effort control, permission fatigue, and supply chain injection

**Claude Opus 4.8: effort control, dynamic workflows, mid-task system updates.** Three features worth noting. *Effort Control* is a new Claude Code per-session setting that trades reasoning depth for speed and rate-limit headroom. *Dynamic Workflows* (research preview) extends subagent orchestration to hundreds of parallel agents within a single session — documented use case is codebase-scale migrations. The most practically significant API change: system-role entries can now appear within the `messages` array, letting agents update Claude's instructions mid-task without breaking the prompt cache. See [Claude Code](../tools/claude-code.md), [Anthropic Client SDK](../tools/anthropic-client-sdk.md).

**Per-action approval gates fail through fatigue, not through bad actors.** Anthropic telemetry puts the approval rate at 93% in practice; a phishing simulation reported 24 of 25 credential exfiltration successes through the mechanism. The practitioner consensus: move the safety guarantee from the dialog to the infrastructure layer. The most common real-world pattern is `--dangerously-skip-permissions` inside a sandboxed container or VPS — disabling prompts entirely while isolating the agent from production credentials. A structurally distinct alternative that hasn't been widely implemented: users approve a high-level task goal rather than individual commands, with the system flagging when specific tool calls may exceed that scope. See [Agentic Loop](../concepts/agentic-loop.md).

**Supply chain prompt injection via dependency output.** A Java property-testing library (jqwik v1.10.0) embedded a prompt injection instruction in its test output, hidden from human terminals using an ANSI escape sequence that erases the line from human-visible output but leaves it readable in CI logs and in agent context that parses that output. The structural problem: whether English text in build or test output is data or an instruction depends entirely on whether a human or a coding agent reads it. Current security scanners miss this — no suspicious syscalls, no obfuscated code, no install hooks. The one concrete mitigation: strip ANSI escape sequences before passing tool output to model context. See [Tool Use](../concepts/tool-use.md).
