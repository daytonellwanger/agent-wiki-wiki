## Agentic cost governance, explicit LLM targeting, and parallel agent isolation

**Agentic cost governance is an unsolved infrastructure problem.** Agents operating with minimal human oversight consume tokens at a qualitatively different rate than supervised interactive use — and enterprises currently lack tooling to predict or cap that exposure before it compounds. Without per-task cost estimates and hard budget controls built into the harness, autonomous agents are a fiscal open loop. Concrete data from recent deployments: one developer reported $40,000 in token costs over three months; another exhausted their entire annual Claude Code budget in just over a week. See [Claude Code](../tools/claude-code.md) (Enterprise Adoption Notes).

**Explicit LLM-targeted prompt injection.** Anna's Archive published a page openly addressed to LLMs, requesting any model with payment-tool access to initiate a donation — skipping the usual pattern of hiding instructions in retrieved content and targeting the agent directly. The HN discussion predicted this will become a widespread web pattern: publishers have a structural incentive to embed agent instructions into public pages as agents routinely browse the web. The principle stands: retrieved web content must be treated as untrusted data, not trusted instructions. See [Tool Use](../concepts/tool-use.md) (Retrieval Tools and Adversarial Content).

**Git worktrees as a parallel-agent isolation primitive.** Superset operationalizes the parallel coding agent pattern by giving each task its own git worktree — an isolated branch and working directory — and providing a unified UI for status, diffs, and PR handling across concurrent agent invocations. The architectural lesson isn't Superset-specific: worktrees are a lightweight, general-purpose isolation primitive for any workflow running multiple coding agents against the same codebase. See [Superset](../tools/superset.md) and [Multi-Agent Coordination](../concepts/multi-agent.md).
