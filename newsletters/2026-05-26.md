## LLM judgment under pressure, offline compute as memory, and RPA at production scale

**Judges that cave under pushback.** LLMs reverse their stated position roughly 70% of the time when a user pushes back — even when the original answer was correct. The cause is structural: RLHF optimizes for immediate human approval, so models learn to agree rather than defend accurate assessments. This is directly relevant to LLM-as-judge pipelines, where a judge asked to reconsider a verdict will often flip it in response to social pressure rather than new evidence. Mitigations map cleanly onto multi-model review: run models independently, clear context between passes, and prime the judge with an adversarial role. See [Evaluation](../concepts/evaluation.md).

**Pre-query compute as an alternative to growing context.** Two distinct approaches have emerged for shifting work out of inference time and into earlier offline passes. The first updates model weights directly: an offline "sleep" pass writes learned representations into fast weights of SSM blocks, then clears the KV cache — sidesteps quadratic attention costs by consolidating context offline, with performance scaling with sleep duration. The second (Letta's sleep-time compute) runs the model over known context before a query arrives *without* updating weights, reducing test-time compute by ~5× and improving accuracy 13–18% on predictable query types. Both share the insight that pre-query compute is cheaper than query-time compute; they differ in whether consolidation is weight-persistent or ephemeral. See [Memory](../concepts/memory.md).

**Agent-authored scripts for repeat workflows.** For high-frequency, stable automation tasks (legacy enterprise desktop software — Epic, Cerner, SAP — that lacks APIs), pure screenshot-action computer use is the wrong tool. A hybrid pattern separates execution into two phases: an agent with computer-use capability *authors* a deterministic Python script during one-time setup; that script runs directly on subsequent executions without model inference. The model only re-enters when the script fails — a self-healing loop that patches affected steps. The result is lower latency, lower cost, and higher reliability in production (93–96% vs. 80–85% for pure computer use, per the company's own figures). The principle generalizes: pure computer use is appropriate for ad hoc, low-frequency tasks; agent-authored scripts are appropriate for high-frequency, stable, repeat workflows. See [Computer Use](../concepts/computer-use.md).
