## Specs as the primary accountability artifact

**When code generation outpaces code review, accountability has to move upstream.** If an LLM produces code faster than engineers can read it, the traditional expectation that developers own every line becomes unenforceable. The proposed response is to shift accountability from code to specifications: the spec (a versioned Markdown document) becomes the artifact humans read and are responsible for; tests verify that generated code conforms to it; the code itself is treated as compiled output. This isn't just a workflow change — it's an organizational one, since it can't be adopted unilaterally by a team.

A practical workflow pattern that follows from this: create plan files first, iterate on spec content with agent assistance, then generate implementation. Spec review replaces code review as the human accountability gate.

One important limit: determining whether code *fully* conforms to a natural-language spec is an unsolved problem (it touches Rice's theorem), so tests provide partial conformance checking, not complete verification. In a spec-driven workflow, the risk propagates upstream — correctness of the output depends on correctness of the spec and correctness of the tests, not just the code.
